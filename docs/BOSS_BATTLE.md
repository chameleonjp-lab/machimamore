# 巨大UFOボス戦（machimamore-3）

基準main: `8d8a725e847974516be9fbc9a0e9e759d6e35683`。2026-10-18。

## 作戦と人数

- 初期UFO50機の出撃・復帰待ち・予備が全て尽きると、即勝利せず3秒の警報へ進む。音が無効でもWARNING表示で伝える。
- 警報後に「BOSS戦開始・巨大UFOを破壊せよ」を表示。既存母艦のモデルが街上空へ進入し、約8秒で所定位置へ到着する。
- 巨大UFOのHPは640（通常80の8倍）。通常50機の有限ロスターとは別管理。ボスは妨害UFOを射出する。
- ボス戦の開始時に妨害UFO3体が実在する。以降、戦闘が継続している各simulation更新終端に3〜6体を保証する。撃破で不足した分は同じtick内に補充し、演出や待ち時間で3体未満にしない。追加射出は3秒間隔、最大6体。ボス自身は数えない。
- 妨害UFOは既存の飛行・レーザー・街攻撃/迎撃経路を利用する。ボス自身には別種のレーザー攻撃を追加しない。
- 巨大UFO撃破で勝利。残存妨害UFOの全滅は要求しない。街全壊・味方全滅が同じtickで起きた場合は従来どおり敗北を優先する。
- ボスへの接触は自機/僚機の撃墜とボス80HP損傷。通常UFOの「接触した双方を全HP破壊」をボスへ流用しない。死亡機体を同tickで除去するため、同じ接触を後続tickで繰り返し加算しない。
- 警報・移動・補充はsimulationの60Hz時計で進み、停止中は凍結。再出撃は初期50機戦から初期化する。

## 得点

| 内訳 | 配点・上限 |
| --- | --- |
| 初期50機 | 従来どおり撃破1,000点/機、実損傷5点/HP。最大70,000点 |
| 巨大UFO | 撃破8,000点、実損傷5点/HP。最大11,200点 |
| 妨害UFO | 最初に射出した6体のIDのみ撃破1,000点/機、実損傷5点/HP。最大8,400点 |
| 7体目以降の妨害UFO | 撃破/損傷の追加点なし。戦闘実績・命中率には記録 |
| 時間 | ボス撃破までの能動時間で従来の30,000÷(1+秒/180)。勝利時のみ |
| 街・味方損失・命中率 | 従来の減点式を継続 |

過剰ダメージは実際に減ったHPまで。ボス640HPと加点対象妨害6体480HPは初期50機4,000HPの台帳から分離する。全妨害機への正当な命中は命中率へ含むが、その改善も従来の最大10,000点減点の範囲内。無限撃破で加点は増えない。数学上の上限は119,600点、実プレイは時間が正なのでこれ未満。旧版と同じ得点尺度とは扱わずルール版を更新した。ランキング・DB・得点保存・外部送信は追加していない。

結果にはボス・妨害の加点を別表示し、初期UFO残機と巨大UFO/妨害UFOの残存状態を区別する。

## 描画と衝突の契約

`src/boss-shape.ts` の形状から本番描画と衝突部品を生成する。本体、ドーム、塔、灯、下部コア、56分割した外周リングを保持し、戦闘中の倍率0.4を共有する。モデルは平行移動のみ。radius=156は照準補助の横幅であり、衝突判定の球ではない。

- 弾・細い射線は凸部品の面で連続判定する。ボスの移動を引いた相対座標を使い、tick間のすり抜けを防ぐ。
- 機体接触・出現位置は球と面/有限辺/頂点の距離・掃引を使う。広い円盤の上空を横幅の球で埋めない。部品の最初の接触だけを採用し、接触80HPを重複加算しない。
- 半径2mのレーザーは凸部品の外側への保守的な面オフセット。球との厳密なMinkowski和ではない。鋭い辺は局所法線の補助面を追加して突出を抑える。近似境界の微小な早期遮蔽は許容し、機体の即死判定には使わない。
- レーザーの時間積分は時間×射線距離の多角形をclipし、入射面の切替・物体の前後入替を分割する。画面上のビーム終点と損傷遮蔽は同じ形状を参照する。ボス破壊後は全ての部品が遮蔽から外れる。
- 部品のAABBで広域除外してから凸判定を実行する。全三角形を無条件に毎tick走査しない。凸部品・法線は起動時に一度構築する。表示用geometryは旧モデルより25個増えるが固定数で、再出撃ごとに増殖しない。

## 検査経路と限界

| 責務 | 検査経路 | 保証しないもの |
| --- | --- | --- |
| 実simulation | `tests/boss-gameplay.test.ts` の合法入力3seed、Easy初期50機→ボス撃破 | 人間の実機操作・全seed攻略 |
| 衝突/形状 | `tests/boss-shape.test.ts` の実mesh射線比較、上空/外周/コア、球掃引、移動遮蔽、微小移動とFloat32境界 | 全入力の形式的証明 |
| 有限台帳/勝敗/補充 | `tests/boss-battle.test.ts` の同時撃破・過剰損傷・敗北優先・pause/reset | 全同時事象の総当たり |
| 実WebGL | `browser-tests/boss-gameplay.spec.ts`。合法入力で到達した状態を本番sceneで描画し、形状/位置/倍率を検査 | UI操作による攻略・実GPU性能・音の実聴 |
| DOM UI | `browser-tests/ui-only`。警報/HP/妨害表示、勝敗別の内訳ラベル/数値/合計/スクロール/再出撃 | 戦闘や3D描画の代用 |
| 既存互換 | 通常UFO/都市/レーザーの既存回帰、`test:review` | 旧バランス証拠の新ルールへの流用 |

不可視衝突は旧公開headで合法入力seed11/29/211すべて失敗する赤テストを固定し、形状修正後に成功。Easyの合法入力勝利回帰も成功。UIの結果ケースは勝利/敗北/中断に分離し、1つの失敗で他の結果操作を未実行にしない。固定fixtureの「切替」を実際の再出撃検査と呼ばない。

`npm run test:evidence` は基準mainでも旧balance証拠のsourceDigest不一致になる。旧証拠は変更しない。新しい長時間バランス証拠は未作成。buildの既存大bundle警告は残る。

ローカルブラウザは環境制限で起動できず、ブラウザ検査は提出headのCIで確認する。UI4viewportの初回検査だけでは実戦受入としない。実3D CIは独立stepとし、UI失敗時も実行する。CIの実描画画像は取得して実見する。iPhone実機・実タッチ攻略・音の実聴・実GPU負荷は未確認。
